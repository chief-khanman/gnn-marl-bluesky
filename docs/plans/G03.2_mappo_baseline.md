## 1. Upstream inputs (what this plan consumes)
- **BlueSky MARLEnv adapter** `marl.interfaces.bluesky_interface.BlueSkyInterface` (D-007 v0),
  exactly as `algorithms/qmix_bluesky.py` already uses it:
  - obs: `float32 (n_agents, 24)`. Width 24 holds only for n ≥ 4 (GAP-21).
  - actions: `Discrete(15)` per agent (5 heading × 3 speed levels, scaled inside the env).
  - reward: scalar team reward, `sum` of the per-agent rewards.
  - state: `float32 (n_agents * 24,)`, i.e. the concatenated observations (v0 placeholder, G04.5).
  - `get_avail_actions()`: all ones, `(n_agents, 15)` bool.
- `marlbench.wrappers.TimeLimit` (S-07) and `marlbench.vec_envs.SubprocVectorEnv` (D-004).

## 3. Design
The same three edits that turned `qmix.py` into `qmix_bluesky.py`, and nothing else:
1. Add `n_agents: int = 5` to `Args`.
2. Add an `elif args.env_type == "bluesky":` branch to `make_env`: `BlueSkyInterface(env_name,
   n_agents)` → `TimeLimit(max_episode_steps)`. The existing `AddAgentID` / `RecordEpisodeStatistics`
   wrapping then applies as for the other env types.
3. Eval envs use `SubprocVectorEnv` when `env_type == "bluesky"` (one BlueSky per process).

The actor is parameter-shared and decentralized: it sees `o^i` (+ agent ID). The critic is
centralized and takes `state` of size `n_agents * 24`, so it is fixed-n. That is the property the
paper cites, and it is kept unmodified (same principle as D-008 for the QMIX mixer).
Because QMIX and MAPPO use the same discrete action set and the same adapter, they are compared
on identical action spaces.

## 6. Risks and alternatives
- **GAP-13 (fairness):** only the MAPPO *critic* is fixed-n, and it's used only in training.
  The actor transfers across n if its input width doesn't depend on n. With `agent_ids=True`, the
  one-hot ID makes the actor's input n-dependent too. With `agent_ids=False`, the actor *can* be
  evaluated zero-shot at n=10. Table 1's "Not transferable without retraining" row is therefore
  true for the critic but contestable for execution. **Recommendation:** in G06.4, evaluate
  MAPPO at n=10 with `agent_ids=False` instead of declaring it non-transferable. This needs
  author input (it touches a paper claim, S-04) and is recorded under GAP-13, not decided here.
- **GAP-12:** BlueSky's native action space is continuous, `Box(2)`. If Q-03 picks continuous
  actions, add `mappo_continuous.py` the same way in a follow-up plan.
- **GAP-21:** the adapter breaks for n ≤ 3, so don't use n=3 until that's fixed.

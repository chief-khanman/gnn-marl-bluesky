Reference method: TransfQMix (Gallici, Martin, Masmitja, AAMAS 2023, arXiv:2301.05334v1). What
we take from it: (1) observations and state are **entity matrices**, not concatenated vectors,
(2) the agent network and the mixer are graph networks whose parameter count does not depend on
the number of entities, (3) the mixer's monotonic weights are **generated from per-agent node
embeddings**, so the mixer has no n-sized layer, (4) execution is decentralized. What we change:
graph convolution (GCN) in the agent and graph attention (GAT) in the mixer instead of
transformers, an explicit sensor-radius graph instead of a learned fully connected one in the
agent, and no recurrent tokens (recurrence belongs to the latency work, GAP-07, on hold).

## 1. Upstream inputs (what this plan consumes)
- `BlueSkyInterface(obs_mode="all_agents")` observation, `float32 (n, 3 + 7·(n−1))`, layout
  `[own (3) | other_1 (7) | …]` (plan GAP-01, D-016). The distance entry of each block is
  `distance_m / ObsConfig.pos_scale_m`.
- Simulator truth `bs.traf.lat/lon/gseast/gsnorth` (already read by the adapter).

## 2. Downstream outputs (what this plan guarantees)
- **Adapter** (`marl/interfaces/bluesky_interface.py`):
  `BlueSkyInterface(..., state_mode="concat_obs" | "entities")`. `"entities"` returns the state as
  a flattened `float32 (n · 7)` entity matrix, one row per agent:
  `[x, y, vx, vy, cos(drift), sin(drift), airspeed]`, positions relative to the fleet centroid
  and scaled by `pos_scale_m`, velocities scaled by `vel_scale_mps`. Default stays `concat_obs`.
  Every `step` info also carries `los_pairs`, `los_onsets`, `min_sep_nm`, `mean_abs_drift_rad`.
- **Metrics** (`marl/metrics.py`, S-11): `pairwise_distance_nm`, `step_safety_metrics`,
  `EpisodeMetrics` wrapper that emits `info["episode_metrics"]` at episode end with the canonical
  names in §3.5.
- **Networks** (`algorithms/gnn_qmix/networks.py`): `GCNAgent`, `GATMixer`, `MLPAgent`,
  `QMixer` (CleanMARL `MixingNetwork`, unmodified, D-008), `VDNMixer`.
- **Training** `python -m algorithms.gnn_qmix.train --config configs/<file>.json [--seed …]`
  and **evaluation** `python -m algorithms.gnn_qmix.evaluate --run-dir <dir> --eval-n 3 6 9 10 20 50`.
- **Run directory** (S-10, D-014): `config.json` (resolved config, `config_sha`, repo commit,
  submodule hashes), `metrics.csv`, `tb/`, `checkpoints/final.pt`, `eval_zero_shot.csv`.
  Formats in §3.6. Consumer: `tools/plot_results.py`, the paper's results section.

## 3. Design

### 3.1 Execution model (resolves GAP-02; answers Q-06)
Centralized training, **decentralized execution**. At execution time vehicle *i* builds its own
observation graph from what its sensor sees, runs the shared GCN agent network on it, and takes
`argmax_a Q_i(o_i, a)`. The mixer is used only to form the training loss. No joint action is
ever selected by a central network.

### 3.2 Observation graph and GCN agent (G05.1, G05.2; resolves GAP-04)
For vehicle *i* the node set is `{i} ∪ {j : dist(i, j) ≤ r_detect}`. A vehicle enters the graph
when it comes inside the sensor radius and leaves when it goes outside. Two neighbors *j*, *k*
are joined when `dist(j, k) ≤ r_detect` (vehicle *i* can compute this from the two relative
positions it measures). Every node has a self-loop.

Node features, width 11: `[own (3) | rel (7) | IS_SELF]`. The self node carries the own
features and `IS_SELF = 1`; a neighbor node carries its 7 relative features. Unused entries are 0.

Network: linear embed 11 → `embed_dim`; `gcn_layers` layers of
`H ← ReLU(D^{-1/2} (A + I) D^{-1/2} H W)`; the self node's embedding is `h_i`;
`Q_i(o_i, ·) = MLP(h_i)`. All weights are shared by all agents and none has an n-sized dimension.
Vehicles outside the radius are masked out of `A` and cannot influence `Q_i` (tested).

### 3.3 Monotonic GAT mixer (G05.3; resolves GAP-03, GAP-20)
Input graph: one node per agent with features `[state_i (7) ‖ h_i]`, `h_i` from the agent network
(gradients flow through it). Edges: `mixer_graph = "full"` (attention learns the weights, as in
TransfQMix) or `"radius"` (same `r_detect` rule on true positions). `gat_layers` layers of
multi-head GAT (dense masked attention), each `g ← ELU(GAT(g)) + g`, give node embeddings `g_i`.

```
W1_i = | Linear(g_i) |                         ∈ R^mix_dim     one row per agent
p    = [ mean_i g_i ‖ max_i g_i ]                              fixed size for any n
b1   = Linear(p),   W2 = | Linear(p) |,   b2 = MLP(p)
Q_tot = ELU( agg_i ( Q_i · W1_i ) + b1 ) · W2 + b2            agg = mean (default) or sum
```

`W1_i ≥ 0` and `W2 ≥ 0`, so `∂Q_tot/∂Q_i ≥ 0` for every agent and every n: the monotonicity
condition of QMIX holds and greedy per-agent actions maximize `Q_tot` (IGM). The mixer is
permutation invariant in the agents. Readouts are mean and max, not sum, so their scale does not
grow with n (GAP-20); with `agg = mean` and the team reward taken as the **mean** over agents,
`Q_tot` stays on one scale for every fleet size.

### 3.4 Training (G05.4) and baselines (G03.1; resolves GAP-13)
- One `SubprocVectorEnv` worker per training fleet size (S-07). GNN-QMIX trains jointly on
  n ∈ {3, 6, 9} (D-017): every loop iteration steps each worker once, and every update draws one
  batch per fleet size and sums the losses before one optimizer step. Batches are single-n, so
  no padding is needed.
- Transition replay (no recurrence), one buffer per fleet size. 1-step TD target with a
  Polyak-averaged target network; bootstrapping stops on termination only, not on truncation.
- Baselines in the same script and loop: **QMIX** (MLP agent, CleanMARL mixer), **VDN** (MLP
  agent, sum), **IQL** (MLP agent, no mixer, each agent regresses on the team reward).
  VDN and IQL read the fixed k-nearest observation (§3.7), are trained jointly like GNN-QMIX and
  can be evaluated at any n. QMIX reads the full observation; its networks are n-specific, so it
  is trained once per fleet size.
- "End-to-end MARL" in C2 / GAP-15 = GNN-QMIX without the PID layer, which is exactly this plan.

### 3.5 Metrics (G06.2), canonical names
All per episode; `T` = steps, pairs = n(n−1)/2, LoS = separation below 5 NM.

| name | definition |
|---|---|
| `ep_return_per_agent` | sum over steps of the mean per-agent reward |
| `ep_length` | T |
| `los_pair_steps` | Σ_t number of pairs in LoS |
| `los_rate` | `los_pair_steps / (T · pairs)` (comparable across n) |
| `los_events` | number of times a pair goes from separated to LoS |
| `los_events_per_agent` | `los_events / n` |
| `conflict_free` | 1 if `los_pair_steps == 0` else 0 (mean over episodes = conflict-free rate) |
| `min_sep_nm` | smallest pair separation in the episode |
| `mean_abs_drift_deg` | mean over steps and agents of the absolute track deviation from the goal bearing |

Not defined here: mission success (GAP-18, Q-14), intervention frequency (needs the PID layer),
emergence measures (GAP-14, removed).

### 3.7 Protocol decisions of 2026-11-25 (D-027…D-030)
- **Fixed k-nearest baseline observation (D-027).** `baseline_k_nearest = 3` for VDN and IQL: own
  features + the 3 nearest other agents, width 24 for any n (the bluesky-gym envs' own design).
  The adapter observation lists others nearest first, so the agent keeps the first k blocks; with
  fewer than k others the missing blocks are zero with distance entry 10.0. Not limited by `r_detect`.
- **Conflict-free spawning (D-028).** `spawn_min_sep_nm = 6.0`: `ConfigurableSectorCR`
  (`simulator/bluesky_marl/custom_envs.py`) rejection-samples start positions so that no pair starts
  inside the 5 NM minimum; if a sector cannot hold the fleet a new sector is drawn. Every method,
  in training and evaluation. All metrics then count only conflicts that arise under the policy.
- **Two airspaces (D-029).** `fixed`: original sector area (2400–3750 NM²), density ∝ n.
  `density`: area range × n / `density_ref_n` (9), so density stays at the n = 9 value. Training
  uses `fixed`; `evaluate` runs every fleet size in both and writes an `airspace` column.
- **Budget per fleet size (D-030).** `steps_per_size = 2 000 000`: every method gets 2M environment
  steps at each training fleet size (joint runs 6M in total; three QMIX runs of 2M). A per-run
  budget would give a single-size model three times the experience at its size. Updates are equal
  too (one batch per size every 8 steps per size). All step-valued settings and the logged `step`
  are per fleet size.

### 3.6 Result files (G06.3)
- `metrics.csv`, long format: `step, split, n_agents, metric, value, n_episodes`.
  `split ∈ {train, eval}`; training rows also carry `loss`, `epsilon`, `steps_per_s`.
- `eval_zero_shot.csv`: `run_id, algo, agent_net, env, train_n, seed, airspace, eval_n, status, episode, <metrics…>`.
  `status = ok` or `not_evaluable` (a fixed-n network asked for another n; one row, no metrics).
- `tools/plot_results.py --runs-dir <dir> --out <dir>` writes `summary_training.csv`,
  `summary_zero_shot.csv`, learning-curve figures and the zero-shot scaling figure.

## 5. Acceptance tests and evidence
- `algorithms/tests/test_gnn_qmix_networks.py`: `Q_i` invariant to neighbor order; vehicles
  outside `r_detect` do not change `Q_i`; one parameter set runs at n = 3, 9, 50; `Q_tot`
  invariant to agent permutation; `∂Q_tot/∂Q_i ≥ 0`; state dict shapes identical for any n.
- `marl/tests/test_metrics.py`: known-answer tests for every metric in §3.5.
- Smoke runs of all four algorithms, a zero-shot evaluation of the GNN-QMIX checkpoint at an
  unseen n, and the plotting tool on the outputs.
- G05.3 is `done` only with 3-seed results from the HPC runs (docs/RUNBOOK.md).

## 6. Risks and alternatives
- The GCN is a weaker aggregator than attention. If it underfits, swap the agent layers for GAT.
- `mixer_graph = "full"` attends over 50 nodes at test time after seeing at most 9. `"radius"`
  is the alternative; it is one config flag.
- With 6 NM spawn separation a fixed sector at n = 50 is close to full; sectors that cannot hold
  the fleet are redrawn, which favors the larger sectors at that size.
- QMIX cannot be evaluated at another n partly because of the full observation it reads
  (GAP-24a). VDN and IQL avoid this with the k-nearest observation (D-027).
